# Конвертер EFKI

Утилита для обработки и конвертации данных о кредитных субъектах и событиях из Excel-файлов в 
специализированные XML-форматы для различных Бюро кредитных историй (ОКБ, Скоринг, КБРС, НБКИ). 
Поддерживает работу через графический (GUI) и консольный (CLI) интерфейсы.
Проект был создан для ПКО, поэтому может не подойти другим организациям; может являться для лишь примером.
Выгрузка Excel является самописной и не имеет какого-либо стандарта, 
в своём проекте вы можете изменить код для [парсинга](app/excel_parser.py) или сделать нужную версию файла.

## Как запускать
Главной точкой входа в приложение является файл `main.py`. 
Запуск маршрутизируется автоматически в зависимости от переданных аргументов.

**Дополнительные параметры CLI:**
* `-j`, `--json`: Путь к файлу конфигурации JSON (по умолчанию `config.json`).
* `-o`, `--output`: Директория для сохранения итоговых XML-файлов (по умолчанию текущая папка `.`).
* `--bki`: Список БКИ для генерации (значения: `okb`, `scoring`, `kbrs`, `nbki`). Указание флага без значений запустит процесс без сохранения файлов.
* `-l`, `--log-level`: Уровень детализации логов (доступны `TRACE`, `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`, по умолчанию `INFO`).
* `-d`, `--debug`: Запуск в режиме отладки (используется фиксированный номер запуска `1111`, конфигурационный файл не обновляется).

## Требования к входному Excel-файлу

1. **Лист данных**: Информация должна находиться на листе с названием `Активные`.
2. **Шапка таблицы**: Вторая строка листа должна содержать заголовки.
3. **Ключевой столбец**: Обязательно наличие столбца с заголовком `# в33` (используется как ID записи).
4. **Колонки**: Требуется наличие стандартных столбцов (Фамилия, Имя, Паспортные данные, Общая сумма долга, Остаток долга и т.д.). 
[Более подробно в excel_parser](app/excel_parser.py) в переменной `standard_columns`.
> Примечание: возможно устарело.

## Возможности программы

### Запуск и системное управление
*   Автоматический выбор режима работы — графический (GUI) при обычном запуске 
или консольный (CLI) при передаче аргументов командной строки [`main`, `app.gui.run`, `app.cli.run`].
*   Поддержка параметров для указания входных файлов, путей конфигурации, директорий вывода, 
выбора конкретных БКИ и активации режима отладки.
*   Глобальная настройка уровней логирования [`setup_app_logging` <- `app.logger_config`]
и работа с JSON-конфигурацией (загрузка, валидация структуры, инкремент счетчика запусков и сохранение) 
[`load_config`, `validate_config`, `save_config` <- `app.utils`].

### Подготовка и нормализация данных
*   Проверка физического наличия файлов Excel и обязательного листа «Активные» [`validate_excel` <- `app.utils`].
*   Преобразование устаревших файлов `.xls` в файлы `.xlsx` для последующей обработки [`convert_xls_to_xlsx` <- `app.utils`].
*   Извлечение данных по заданному списку колонок и приведение их к единой структуре словаря [`parse_active_sheet` <- `app.excel_parser`].
*   **Очистка данных:** 
    *   Удаление заглушек, маркеров отсутствия данных и неразрывных пробелов из ФИО [`clean_fio` <- `app.utils`].
    *   Нормализация текстовых полей (место рождения, кем выдан) с удалением спецсимволов и приведением к верхнему регистру [`clean_issuer` <- `app.utils`].
    *   Преобразование дат: `ГГГГ-ММ-ДД` [`format_date` <- `app.utils`].
    *   Кастомизация файла: стили, сортировка, автофильтры и ширина колонок [`customize_excel` <- `app.aggregatiom`].

### Обработка финансовых операций
*   Извлечение данных из файла возвратов, агрегация платежей по составному ключу, пересчет остатка долга, 
обработка «перевозвратов» и установка статусов на основе справочников 
[`process_excel_returns`, `process_other_closures` <- `app.aggregation`].
*   Приведение денежных значений к строковому виду с двумя знаками после запятой 
и заменой разделителей (для XML) [`format_sum_to_str` <- `app.utils`].

### Генерация XML для БКИ
*   Централизованное управление конвертацией (`run_conversion`, `generate_xml_*` <- `app.orchestrator`).
*   Формирование иерархии XML, включая:
    *   Блок организации (`<Source>`), титульные данные субъекта (`<Title>`) и общий блок данных (`<Data>`).
    *   Кредитные события: **2.3** (изменение), **2.5** (завершение договора) и **2.11.2** (добавление).
*   Формирование блоков просрочки и платежей, включая вычисление количества дней просрочки на текущую дату 
(`calculate_days_difference`, `build_fl_27_28` <- `app.convertor`).
*   Финальная сборка XML-дерева, форматирование и сохранение готовых файлов 
(`finalize_and_save_xml`, `save_xml` <- `app.convertor`).
